1. System Overview

GlareTracker is a real-time desktop application that simulates and visualizes how headlight glare from an oncoming vehicle strikes a driver's windshield. The system:

  1. Captures the driver's face via laptop webcam
  2. Tracks the iris position using MediaPipe Face Mesh (468+ landmarks)
  3. Converts pixel coordinates to real-world centimetre positions
  4. Computes where the eye-to-light ray intersects the windshield plane
  5. Visualizes everything in a 5-panel dashboard:
    • Live camera feed with iris overlay
    • 3D scene (OpenGL) with windshield, eye, lights, and ray
    • 2D windshield front-view with glowing glare spot
    • Real-time telemetry readout
    • Interactive controls panel

4. Software Architecture

4.1 Design Principles

  • Separation of Concerns: Each module has a single responsibility — geometry math knows nothing about Qt, widgets know nothing about tracking logic.
  • MVC-inspired: ControlsPanel (View/Input) → TrackingController (Controller/Logic) → Scene3DWidget, ReadoutPanel (View/Output)
  • Non-blocking I/O: Camera runs in a QThread; GUI thread only processes signals.
  • In-place updates: 3D objects are created once and updated via setData() for 60+ FPS.

4.2 Dependency Graph

5. Module-by-Module Breakdown

5.1 config.py — Configuration

~20 lines • No dependencies

Contains the TrackingConfig frozen dataclass. This is an immutable snapshot of tracking parameters that gets passed from the GUI thread to the camera thread. Being frozen (immutable) makes it inherently thread-safe.

@dataclass(frozen=True)
class TrackingConfig:
    screen_w_cm: float = 34.5    # windshield width
    screen_h_cm: float = 19.5    # windshield height
    eye_dist_cm: float = 50.0    # driver distance from screen
    camera_x_cm: float = 0.0     # camera X offset
    camera_y_cm: float = 0.0     # camera Y offset
    camera_z_cm: float = 30.0    # camera height

5.2 geometry.py — Intersection Math

~50 lines • Pure Python + math • No Qt dependencies

Two pure functions with no UI dependencies — easy to unit test independently:

compute_intersection(eye_cm, light_cm)

Computes where the ray from the driver's eye toward the light source crosses the windshield plane at Y = 0 using parametric line-plane intersection:

# Parametric form: P(t) = eye + t × (light - eye)
# Windshield plane: Y = 0
# Solve: eye.y + t × (light.y - eye.y) = 0
# Therefore: t = -eye.y / (light.y - eye.y)

t = -y1 / dy
if not 0.0 <= t <= 1.0:   # intersection must be between eye and light
    return None
return (x1 + t * (x2 - x1), 0.0, z1 + t * (z2 - z1))

The t parameter is clamped to [0, 1] so only intersections between the eye and light are reported — not behind the driver or beyond the light.

pixel_to_cm(eye_x_px, eye_y_px, ...)

Converts the pixel-space iris midpoint (from MediaPipe) to approximate real-world centimetre coordinates, mapping the camera frame dimensions to the physical screen dimensions.

5.3 camera.py — Webcam Capture Thread

~120 lines • QThread + OpenCV + MediaPipe

Runs in a background QThread so the GUI never freezes during camera I/O (~33ms per frame).

Key Design Decisions

DecisionRationale
Uses cv2.CAP_DSHOWDirectShow backend gives instant camera startup on Windows (default MSMF can freeze 3-8 seconds)
QImage.copy()Qt must own the buffer — without copy, the numpy array could be garbage-collected causing crashes
BGR→RGB in worker threadOffloads CPU work from the GUI thread
Iris landmarks 468 & 473MediaPipe's true iris centre landmarks (not 474/469 which are ring points)
try/except/finallyEnsures camera and MediaPipe are always released, even on crash

Signals Emitted

SignalDataWhen

eye_detected(x, y, z)Eye position in cmWhen a face is found

5.4 tracking.py — Tracking Controller

~200 lines • Core business logic

This is the most important architectural extraction. Previously all this logic lived inside MainWindow (violating Single Responsibility). Now TrackingController is a plain Python class that:

  • Receives raw eye coordinates from the camera thread
  • Applies calibration offsets
  • Computes intersections for all light sources
  • Updates all UI panels (3D, 2D, readout)
  • Manages light movement simulation
  • Counts FPS

Responsibilities

MethodWhat it does
on_eye_detected(x, y, z)Applies calibration, triggers process_tracking()
on_eye_lost()Clears all visual indicators
process_tracking(eye_cm)Computes intersections for all lights, updates 3D/2D/readout
calibrate()Sets current eye position as centre reference
start_movement()Begins light animation
advance_movement()Moves lights one tick (called by QTimer every 50ms)
on_params_changed()Reacts to control panel changes
update_fps()Calculates frame rate from timestamps

Calibration System

On first face detection, the system auto-captures a baseline — the driver's current position becomes (0, 0, windshield_centre). This offset is subtracted from all future readings. The "Calibrate" button lets the user re-set this baseline manually.

5.5 window.py — Main Window

~180 lines • Layout + signal wiring only

After the refactor, MainWindow is a thin shell that only handles:

  1. Widget creation — instantiates all 5 panels
  2. Layout — arranges them in nested QSplitters
  3. Signal wiring — connects camera signals → controller, buttons → actions
  4. Stream toggle — starts/stops the camera thread
  5. Responsive resize — switches to vertical layout on narrow windows

Zero tracking logic, zero geometry, zero calibration math.

5.6 widgets/ — UI Components

VideoWidget (video.py, ~35 lines)

A QLabel that receives QImage frames and displays them with aspect-ratio preservation. Shows placeholder text when the stream is stopped.

Windshield2DWidget (windshield_2d.py, ~140 lines)

Custom-painted widget using QPainter. Draws:

  • Rounded windshield outline with aspect-ratio preservation
  • Dashed crosshair grid lines (centre reference)
  • Edge labels: TOP, BOTTOM, LEFT, RIGHT
  • Glowing radial gradient for in-bounds glare spots (yellow/orange)
  • Red dashed circle for out-of-bounds indicators
  • Windshield border turns red when any glare is out of range

Scene3DWidget (scene_3d.py, ~340 lines)

Wraps PyQtGraph's GLViewWidget (OpenGL). The largest widget because it manages many 3D objects:

ObjectTypeColourDescription
WindshieldGLMeshItemCyan (semi-transparent)Vertical quad at Y=0
Grid floorGLGridItemWhite (faint)Spatial reference
AxesGLLinePlotItem × 3RGBX/Y/Z direction indicators
Eye pointGLScatterPlotItemBlueDriver iris position
Light sourcesGLScatterPlotItem × 4OrangeUp to 4 headlights

Performance strategy: All items are created once during __init__ and updated in-place via setData(). Hidden items are moved to (9999, 9999, 9999) rather than removed/re-added, achieving 60+ FPS.

Includes a floating ⚙ settings overlay for changing colours, label sizes, and toggling eye/light visibility.

ReadoutPanel (readout.py, ~90 lines)

Monospace (Consolas) text readout with colour-coded status. Features a dynamic intersection list that grows/shrinks based on the number of active light sources.

ControlsPanel (controls.py, ~140 lines)

All user inputs organised in collapsible groups:

  • Windshield Width/Height (cm)
  • Camera Position X/Y/Z
  • Driver Distance
  • Vehicle Category (Motorcycle / Car / Extreme — determines headlight count)
  • Light Source X/Y/Z
  • Movement pattern selector + Play/Stop
  • Start/Stop Stream, Calibrate, Reset 3D View buttons

The get_light_positions() method applies vehicle-specific headlight offsets to the base position.

5.7 styles.py — Dark Theme

~60 lines

A single DARK_STYLESHEET string constant applied to the entire application. Uses a GitHub-dark inspired colour palette with styled QGroupBox, QDoubleSpinBox, QPushButton, and QSplitter handles.

5.8 app.py — Entry Point

~15 lines

Creates QApplication, sets the Fusion style, loads the window icon, creates MainWindow, and runs the Qt event loop.

7. Threading Model

┌─────────────────────────────────────┐ ┌─────────────────────────┐ │ GUI THREAD (main) │ │ WORKER THREAD │ │ │ │ (VideoCaptureThread) │ │ MainWindow │ │ │ │ TrackingController │ │ cv2.VideoCapture │ │ All Widgets │ │ MediaPipe FaceMesh │ │ QTimers │ │ BGR → RGB conversion │ │ │ │ QImage construction │ │ ◄── signals (thread-safe) ────────│◄───│ │ └─────────────────────────────────────┘ └─────────────────────────┘
Thread safety: Qt signals across threads are automatically queued (delivered via the event loop). The TrackingConfig dataclass is frozen/immutable, so it can be safely read from the worker thread after being set from the GUI thread.

8. Feature Details

8.1 Vehicle Light Modes

CategoryLightsOffsets from base position
Motorcycle1(0, 0, 0)
Four-Wheeler/Car2(-8, 0, 0) and (+8, 0, 0)
Extreme Vehicle4(±10, 0, -4) and (±10, 0, +4)

8.2 Light Movement Simulation

Three animated patterns move the entire headlight cluster as a rigid body:

PatternDescription
Coming straightLight approaches from far (Y+240) to near, with slight lateral sine wave
Coming at opposite sideLight sweeps laterally across 180cm (X axis)
Long distanceLight approaches from very far (Y+700) to near

Animation runs at 50ms intervals (20 ticks/second). Phase advances by 0.0125 per tick, completing one full cycle every 80 ticks (4 seconds).

8.3 3D Scene Settings Overlay

A floating panel anchored to the top-right of the 3D view allows:

  • Colour customization for windshield, eye, and light objects (via QColorDialog)
  • Label font size adjustment (slider, range 8–32)
  • Toggle visibility of eye points and light source points

8.4 Responsive Layout

When the window width drops below 1050px, the main splitter switches from horizontal to vertical orientation, stacking the sidebar below the viewport panels.

10. Glossary

TermDefinition
IntersectionThe point where the eye-to-light ray crosses the windshield plane (Y=0)
In-boundsAn intersection that falls within the windshield rectangle dimensions
Calibration offsetThe difference between the driver's actual position and the windshield centre, used to zero the coordinate system
BaselineThe first captured eye position, auto-set on first face detection
Movement phaseA 0.0–1.0 value representing progress through one animation cycle
GLTextItemPyQtGraph's 3D text label rendered as a billboard (always faces camera)
