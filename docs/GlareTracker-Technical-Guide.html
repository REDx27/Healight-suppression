1. System Overview

GlareTracker is a Windows desktop application. It estimates the driver's eye position from a webcam, creates rays from the eye toward one or more configurable light sources, and finds where those rays meet a virtual windshield.

Webcam frame → MediaPipe iris landmarks → pixel-to-centimeter position → ray/plane intersection → 2D, 3D, and telemetry updates
LayerTechnologyResponsibility
CaptureOpenCV + QThreadRead frames without freezing the GUI.
DetectionMediaPipe Face MeshLocate iris landmarks 468 and 473.
ModelNumPy + helper functionsConvert coordinates and calculate intersections.
InterfacePyQt5Controls, camera preview, readout, and application lifecycle.
VisualizationQPainter + pyqtgraph OpenGLShow glare positions and 3D rays.

3. Runtime Data Flow

Startup

  1. main() creates QApplication, applies the Fusion style, constructs MainWindow, and starts the Qt event loop.
  2. MainWindow creates all panels and the VideoCaptureThread, connects signals, pushes initial settings, and starts timers.
  3. The scene is initially prepared with hidden/off-screen tracking markers.

Frame processing

  1. Pressing Start Stream starts the worker thread.
  2. OpenCV opens camera index 0 using DirectShow, requests 640×480 at 30 FPS, and mirrors each frame.
  3. MediaPipe processes an RGB copy. When a face is found, landmarks 468 and 473 are averaged into an iris midpoint.
  4. The midpoint becomes an eye position in centimeters and is emitted through eye_detected.
  5. The GUI callback applies calibration, calculates intersections, and updates every view.

Signals and ownership

SignalEmitted byConnected toMeaning
frame_ready(QImage)VideoCaptureThreadVideoWidget.update_frameDisplay the latest camera frame.
eye_detected(x,y,z)VideoCaptureThreadMainWindow._on_eye_detectedDeliver a detected eye position.
eye_lost()VideoCaptureThreadMainWindow._on_eye_lostClear tracking visuals and show no-face status.
Threading rule: camera capture and MediaPipe inference run in VideoCaptureThread. Qt signals transfer results to the GUI thread, so widgets are updated in the thread that owns them.

4. Geometry and Coordinate Model

The application uses centimeters and a right-handed conceptual scene:

  • X: lateral position, left/right.
  • Y: depth. The windshield is at Y = 0; the driver is normally behind it at negative Y; light sources are in front at positive Y.
  • Z: vertical height.

Pixel mapping

pixel_to_cm() maps the iris midpoint from the camera image into the configured windshield dimensions. Horizontal image center maps to X=0. Image Y is inverted so higher screen positions produce higher Z. Eye depth is the configured negative eye_dist_cm.

x = (pixel_x − frame_width / 2) / frame_width × screen_width
y = −eye_distance
z = (frame_height / 2 − pixel_y) / frame_height × screen_height + screen_height / 2

Ray intersection

compute_intersection(eye_cm, light_cm) parameterizes the line from eye P₁ to light P₂ as P(t)=P₁+t(P₂−P₁). For the windshield plane Y=0:

t = −y₁ / (y₂ − y₁)
intersection = (x₁ + t(x₂−x₁), 0, z₁ + t(z₂−z₁))

The function returns None when the ray is parallel to the plane or when the crossing lies outside the segment (t is not between 0 and 1). A returned point is in range only when −width/2 ≤ X ≤ width/2 and 0 ≤ Z ≤ height.

Main tracking algorithm

_on_eye_detected(x, y, z)
  observed = (x, y, z)
  capture baseline on first observation, if needed
  subtract calibration offset
  _process_tracking(adjusted_eye)

_process_tracking(eye)
  choose simulated or configured lights
  update 3D eye, lights, and rays
  for each light:
    intersection = compute_intersection(eye, light)
    classify as mathematical miss, out of bounds, or valid
    convert valid/display points to normalized 2D coordinates
  update 3D intersections, telemetry, and 2D glare spots

Calibration

The first detected eye is automatically used as a baseline. The X and Z offsets move that observed point to the windshield center; Y is intentionally left unchanged. The Calibrate Center button captures the latest observed eye again.

Missing-face behavior

_on_eye_lost() clears the latest eye, moves 3D tracking objects off-screen, clears the 2D glare, empties intersection readouts, and reports NO FACE.

6. User Interface and Controls

Five-panel dashboard

  1. Camera: mirrored feed with iris overlays.
  2. Windshield front view: proportional windshield rectangle, labels, glowing valid glare spots, and red out-of-range indicators.
  3. 3D scene: windshield plane, axes, webcam, eye, light sources, ray lines, and intersections.
  4. Telemetry: eye coordinates, light mode, FPS, status, and per-light intersection results.
  5. Controls: dimensions, camera location, driver distance, vehicle category, source position, movement simulation, stream, calibration, and reset.

Light source modes

Vehicle categorySources
MotorcycleOne source at the configured position.
Four-Wheeler/CarTwo sources offset ±8 cm on X.
Extreme VehicleFour sources in a ±10 cm X and ±4 cm Z arrangement.

Movement simulation

The 50 ms movement timer translates the complete light arrangement while preserving the relative arrangement of sources. The three modes vary lateral crossing, approach direction, and distance. Simulation uses the same intersection pipeline as live tracking, so it is useful for checking visualization behavior without changing the geometry algorithm.

Performance details

3D objects are created once and updated in place. Repeated positions are skipped using cached tuples. Unused source slots are moved to coordinates near 9999 so the scene supports up to four sources without repeatedly adding/removing OpenGL items.

7. Packaging and Installation

requirements.txt → PyInstaller spec → dist/GlareTracker.exe → Inno Setup installer
  1. Run ./build_exe.ps1 in PowerShell.
  2. The script installs dependencies from requirements.txt.
  3. PyInstaller reads glare_tracker.spec, collects package data and hidden imports for MediaPipe and pyqtgraph, embeds the icon, and creates a windowed executable.
  4. The executable is copied to the project root as GlareTracker.exe.
  5. If iscc.exe is on PATH, Inno Setup creates installer-output/GlareTracker-Setup.exe.

The installer uses a per-user location under %LOCALAPPDATA%\Programs\GlareTracker, creates a Start Menu shortcut, and offers an optional Desktop shortcut. The standalone shortcut script points directly to the root executable.

8. Running, Testing, and Troubleshooting

Development run

python -m pip install -r requirements.txt
python glare_tracker.py

Basic functional checklist

  • Application starts with no import errors.
  • Start Stream opens the webcam and shows a mirrored frame.
  • A detected face changes status to TRACKING and updates eye coordinates.
  • Moving light coordinates changes rays and intersection results.
  • Changing the vehicle category changes the number of sources.
  • Calibrate Center moves the current eye reference to the windshield center.
  • Stop Stream releases the camera and clears visual tracking state.
  • Closing the window stops timers and waits for the capture thread.

Common issues

SymptomLikely cause and action
Camera feed stays stoppedCamera unavailable, permissions, or another application owns it. Check Windows camera privacy settings and camera index 0.
No face detectedImprove lighting, face the camera, and keep the eyes visible. MediaPipe needs a usable face image.
3D view is blankCheck Windows graphics/OpenGL support and the PyOpenGL installation.
All intersections are out of rangeReview windshield dimensions, eye distance, and light Y/Z positions. The ray must meet the plane inside its X/Z bounds.
Packaged app cannot find iconConfirm assets/glaretracker-icon.ico is included by the spec and rebuild with --clean.
Model limitation: pixel-to-centimeter conversion is an approximation based on the configured image-to-windshield dimensions and fixed eye distance. It is not a calibrated camera-pose or depth-estimation system.
Good extension points: move geometry helpers into a separate module, add unit tests for intersection edge cases, add camera calibration, and store user settings with QSettings.
